# 設計メモの書き方

設計メモは 2 つのファイルからなる。

- `notes/design.md`: 現在の設計と、そこに至るまでに却下した案
- `notes/open-questions.md`: 未決の問い。次の作業はここから選ぶ

エージェントは見出しを grep し、該当する節だけを読む。以下のルールは、その読み方が成り立つようにするためのものである。

## 内容

- 現状に合わせて書き換える。古くなった記述は消してよい。消すときはコミットメッセージに理由を書く
- 却下した案は、採用した案と同じ節に `#### 却下: <案>` として理由とともに残す。同じ案が再び提案されるのを防ぐため
- 判断を見直したときは `#### 再評価: <何が変わったか>` を追記するか、本文を書き換える
- 外部の状態に依存する判断には、本文に前提を書く。ライブラリの版、実測した環境、「〇〇になったら見直す」という条件など。日付は書かず、時系列は git 履歴に任せる

## 目次の整合性

- 節（`##`）を追加・改名・削除したら、同じコミットで目次も更新する。目次の行は節の見出しと同じ番号・名前にする
- 目次の要旨は、その節を読むべきか判断できる 1 行にとどめる。小節は列挙しない
- 節番号は振り直さない。新しい節は末尾に足す

## 節の独立性

- 各節は、その節だけを読んで意味が通るように書く
- 他の節の内容が前提になるときは、繰り返さずに `§n.m` で参照する。「上で述べた」「前節」のような位置に頼る書き方はしない

## 見出しの使い方

- `##` の中はトピックごとに `### n.m` で分ける。`####` は個別の論点、却下、再評価に使う
- 見出しは grep で当たる具体的な名前にし、ファイル内で一意にする。「その他」「補足」は使わない
- 1 つの見出しの下に複数の論点を詰め込まない

## 未決の問い

- 問いは `notes/open-questions.md` に `## <問い>` として足す
- 決まったら `notes/design.md` の該当する節に書き、`notes/open-questions.md` から消す
- 却下で決着した場合も、却下理由は `notes/design.md` に残す
